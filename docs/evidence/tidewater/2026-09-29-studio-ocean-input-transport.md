# Tidewater — entrées FFT vérifiées dans Studio

Le calcul océan de la promenade native utilisait encore les shaders et uniformes du bundle de probe directement. Studio n'avait aucun paquet océan à charger. Cette tranche rend transportables les **entrées** de la FFT, sans présenter les sorties pré-calculées du probe comme une surface d'eau jouable.

`package-ocean-assets.py` a extrait du bundle `preview-scene-bundle-fish-stand-content-fish-011` épinglé à `c739c737914261991fd9aba21c4372e7e9cafa31527f7a4139001a4db8e9b335` les neuf kernels WGSL, les uniformes initiaux et le témoin de frame 120, la métadonnée `ocean.json` et la licence MIT. Les 13 fichiers `ocean/` sont identiques à ceux du bundle météo normale `preview-scene-bundle-clear-004`. Le nouveau paquet local contient 14 fichiers, 107 088 octets ; SHA-256 du manifeste `ba9da93d9012341d180712e1ddcf8143f7878770e19ce7ba477269aa24e9b879`.

`OceanPackage` impose le commit source `1438b1abfcaee3267092b75573014f4d9b4a983c`, la liste exacte des entrées, des limites de taille, l'empreinte de chaque payload et les empreintes internes de `ocean.json`. Il refuse l'ajout d'une texture de déplacement calculée. Le test de falsification du manifeste externe et le test sur le paquet acquis passent. Le chargement navigateur est optionnel et séquentiel via `ocean_sha256` dans `forge-imports/buildings.json` ; l'ancien manifeste sans océan reste lisible.

Contrôles exécutés : `cargo test -p forge_assets tidewater_ocean --locked --offline` (test synthétique PASS), puis `FORGE_TIDEWATER_OCEAN_PACKAGE=.../ocean-package-001 cargo test -p forge_assets acquired_fft_inputs_match_both_manifests --locked --offline -- --ignored` (paquet réel PASS), `cargo check --locked --offline --target wasm32-unknown-unknown -p forge_studio --no-default-features --features web -j1` (PASS), construction release WASM (PASS), test Python de préparation de site (PASS). Le contrôle `cargo fmt --all -- --check` ne peut pas parcourir un exemple sans le fichier `tidewater_plant_probe/terrain_ao.rs`, absent du worktree courant ; les fichiers modifiés ici ont été formatés séparément et `git diff --check` passe.

La candidate locale `studio-imported-playtest-candidate-ocean-016/forge-studio-candidate.exe` (SHA-256 `c4a9b2f147f511f10531d569b9d5ec46cad48a01e04cf38b0eda3df359566968`) incorpore le WASM `1fa4d9d829c095cbf66d982277663da5807b7fcaca063df27177c298832606ca` et la bibliothèque à six pins, dont le paquet océan. `Invoke-FishStandStudioSmoke.ps1` passe sur une copie isolée (`studio-imported-playtest-smoke-ocean-019`) : ouverture, pose, sauvegarde, réouverture, simulation et déplacement. Le succès implique que le chargeur navigateur a obtenu et validé le paquet avant publication de la bibliothèque ; il ne prouve pas l'exécution GPU de la FFT.

**Reste ouvert :** déplacer le graphe FFT de l'exemple natif vers un service Bevy réutilisable, raccorder son horloge et ses textures à Studio, empaqueter les entrées du rivage/matériau optique, afficher l'eau, puis comparer poses et animation avec la référence WebGPU. L'océan n'est pas encore visible dans le viewport Studio.
